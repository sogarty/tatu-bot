# Развёртывание Tattoo Bot на Render

Эта инструкция — для людей без опыта программирования. Следуйте шагам по порядку.

---

## 📋 Что у нас есть

- **backend** — FastAPI + Telegram-бот (эта папка `deploy/`)
- **frontend** — Mini App в папке `web/`; production FastAPI отдаёт его по `/app/`

---

## ⚠️ Важное про хостинг

У Render есть **Free Web Service**, но это режим демо/проверки, а не гарантия
24/7: сервис засыпает после периода без входящих запросов, просыпается примерно
за минуту, может быть перезапущен, а локальные файлы теряются. Пинг UptimeRobot
уменьшает вероятность сна, но не даёт SLA и не защищает от перезапусков или
лимита бесплатных часов.

Для настоящего production выбирай постоянно работающий paid web service или
другой VPS/PaaS с подтверждённым always-on режимом. Отдельно нужна PostgreSQL
с понятными условиями хранения и резервного копирования. Бесплатные тарифы
провайдеров могут засыпать, ограничивать квоты или удалять базу по сроку.

Текущая `render.yaml` намеренно оставляет `plan: free`, чтобы проект можно было
проверить без оплаты. Не называй такой deployment независимым 24/7 production.

## ШАГ 1. GitHub-репозиторий для backend

1. Зайдите на [github.com](https://github.com) и войдите в аккаунт.
2. Нажмите зелёную кнопку **New** (или **Create a new repository**).
3. Придумайте имя репозиторию, например `tattoo-bot`.
4. Поставьте галочку **Private** (чтобы код был виден только вам).
5. Нажмите **Create repository**.
6. Нажмите **Add file** → **Upload files**.
7. Перетащите в окно браузера **ВСЕ файлы и папки** из папки проекта (`deploy/`):
   - `app/` (папку целиком)
   - `alembic/` (папку целиком)
   - `tests/`
   - `web/`
   - `.gitignore`
   - `alembic.ini`
   - `README_DEPLOY.md`
   - `requirements.txt`
   - **НЕ загружайте**: `.env`, `*.db`, `__pycache__`, `venv`, `logs`
8. Прокрутите вниз и нажмите **Commit changes**.

✅ Готово! Backend загружен на GitHub.

## ШАГ 2. Frontend Mini App

Рабочий Mini App не нужно размещать отдельно: FastAPI уже монтирует весь каталог
`web/` по адресу `/app/`, включая `assets/portfolio/`. Это важно, потому что
`app.js` использует same-origin API `/api/v1/`.

После запуска backend рабочий адрес будет:
`https://ВАШ-СЕРВИС.onrender.com/app/`.

GitHub Pages можно использовать только для отдельного статического preview.
Не указывай его как рабочий `WEBAPP_URL`, иначе API Mini App будет искаться
на домене Pages.

## ШАГ 3. Создание сервиса на Render

1. Зайдите на [dashboard.render.com](https://dashboard.render.com) и войдите.
2. Нажмите **New** → **Public Web Service** (да, «Public» — это просто тип сервиса, он может быть приватным).
3. Выберите ваш GitHub-репозиторий `tattoo-bot` (backend).
4. Заполните форму. Если GitHub-репозиторий содержит **содержимое папки
`deploy/` в корне**, используйте следующие команды:

| Поле | Что написать |
|------|-------------|
| **Name** | любое, например `tattoo-bot-api` |
| **Region** | ближайший к вам (например **European Moscow** или **Oregon**) |
| **Branch** | `main` |
| **Root Directory** | оставьте пустым |
| **Runtime** | **Python 3** |
| **Build Command** | `pip install -r requirements.txt` |
| **Start Command** | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| **Python Version** | **3.12** |

Если `deploy/` остаётся вложенной папкой монорепозитория, укажи `Root Directory:
deploy`; тогда `requirements.txt`, `app/`, `web/` и `render.yaml` должны
разрешаться относительно этой директории. Не смешивай два layout в одном
deployment.

5. Нажмите **Create Web Service**.
6. Сервис начнёт деплой. Это займёт 3–5 минут. Сначала будет красная полоса «Building»…

## ШАГ 4. Переменные окружения (секреты)

**НИКОГДА не записывайте токены в код!** Они хранятся только в настройках Render.

В настройках вашего сервиса на Render найдите секцию **Environment** и добавьте переменные:

| Переменная | Значение | Как получить |
|-----------|---------|-------------|
| `BOT_TOKEN` | ваш токен бота | от [BotFather](https://t.me/BotFather) |
| `MASTER_TG_ID` | ваш числовой ID в Telegram | от [@userinfobot](https://t.me/userinfobot) |
| `MODE` | `webhook` | просто напишите это слово |
| `WEBHOOK_BASE_URL` | HTTPS-адрес сервиса без `/webhook` | адрес появится после создания сервиса |
| `WEBHOOK_SECRET` | длинная случайная строка | `python -c "import secrets; print(secrets.token_urlsafe(32))"` — или сгенерируйте на [randomkeygen.com](https://randomkeygen.com) |
| `ALLOWED_ORIGINS` | origin сервиса без завершающего `/` | например `https://tatu-bot.onrender.com` |
| `WEBAPP_URL` | `https://ВАШ-СЕРВИС.onrender.com/app/` | рабочий адрес Mini App |
| `DATABASE_URL` | обязательная PostgreSQL connection string | Neon, Render Postgres или другой PostgreSQL-провайдер |
| `ENVIRONMENT` | `production` | просто напишите это слово |

**Важный порядок:**
1. Создайте сервис и сразу заполните PostgreSQL, `BOT_TOKEN`, `MASTER_TG_ID`,
   `WEBHOOK_SECRET`, `WEBAPP_URL`, `ALLOWED_ORIGINS`, `ENVIRONMENT=production`.
2. Скопируйте адрес сервиса (вида `https://tattoo-bot-api-xxxx.onrender.com`).
3. Укажите его в `WEBHOOK_BASE_URL` без `/webhook`.
4. Перезапустите сервис: **Dashboard** → **Manual Deploy** → **Deploy latest commit**.

`ALLOW_EPHEMERAL_DATABASE=true` не устанавливайте в production: это только
локальный флаг для тестов с временной SQLite-базой.

## ШАГ 5. Проверка: /health

Откройте в браузере:
```
https://ВАШ-СЕРВИС.onrender.com/api/v1/health
```

Для production ожидается:
```json
{"status": "ok", "data_persistent": true, "database_backend": "postgresql", "webhook_ready": true}
```

Если возвращается `503`, `data_persistent` равно `false` или `webhook_ready`
равно `false`, production-конфигурация не готова. Не продолжайте проверку бота
до исправления этого.

## ШАГ 6. Мониторинг (только уменьшает cold start)

Web Service на Render засыпает, если нет запросов. Чтобы он был всегда на связи:

1. Зайдите на [uptimerobot.com](https://uptimerobot.com) и создайте бесплатный аккаунт.
2. Нажмите **Add Monitor** → **HTTP**.
3. Вставьте адрес: `https://ВАШ-СЕРВИС.onrender.com/api/v1/health`
4. Интервал: **5 минут**.
5. Нажмите **Save**.

Это может уменьшить вероятность сна, но не превращает Free Service в 24/7
гарантированный backend. Для webhook и важных заявок нужен always-on тариф.

## ШАГ 7. Проверка бота

1. Откройте вашего бота в Telegram.
2. Напишите `/start`.
3. Если бот отвечает — всё работает! 🎉

## ⚠️ Ограничения тарифа Render

| Ограничение | Что это значит |
|------------|----------------|
| **Free Web Service** | засыпает после простоя, около минуты на пробуждение, 750 instance-hours/мес |
| **Always-on Web Service** | платный тариф; актуальную цену проверь в Dashboard Render |
| **Нет постоянного диска** | Файлы, созданные во время работы (например, SQLite-база), **НЕ сохраняются** после перезапуска |
| **Минимальные ресурсы** | 512 МБ RAM, ~0.5 vCPU — хватает для небольшого бота |
| **Бесплатная база Render** | ограниченный срок/квота; не считать бессрочным хранилищем |

### 💾 База данных — что делать?

SQLite-база на Render **не сохраняется** между перезапусками и намеренно
отклоняется production-конфигурацией. Для продакшена нужно подключить
внешнюю PostgreSQL-базу.

**Самый простой бесплатный вариант: [Neon](https://neon.tech)** (PostgreSQL Serverless).

Переход на Neon:
1. Создайте бесплатный проект на [neon.tech](https://neon.tech).
2. Скопируйте connection string (вида `postgresql://...`).
3. Вставьте его в переменную окружения `DATABASE_URL` на Render.
4. Проверь лимиты, срок хранения и backups выбранного плана. Neon/другой
   внешний PostgreSQL лучше Render Free Postgres для длительного теста, но
   бесплатный план всё равно не является SLA или резервной копией.

## 📁 Что реализовано в исходниках

Возможности ниже доступны на live-сервисе после публикации соответствующей
версии кода. Перед выкладкой проверь `/api/v1/health`: production-сервис должен
использовать PostgreSQL и отвечать `data_persistent: true`; проверяй также
`webhook_ready: true`, если бот работает через webhook.

В этой версии исходников реализованы:

1. Telegram WebApp `initData` с серверной HMAC-проверкой и ownership заявок.
2. Mini App, который FastAPI отдаёт через `/app/` вместе с API.
3. Мастерский кабинет в Mini App: заявки, статусы, календарь, настройки и
   серверное управление портфолио.
4. Портфолио хранится в PostgreSQL: метаданные, публикация, сортировка и
   загруженные изображения. Новая загрузка не зависит от локального диска
   Render и доступна через `/api/v1/portfolio/{id}/image`.

## Серверное управление портфолио

Публичный список опубликованных работ:

```text
GET /api/v1/portfolio
```

Только мастер через валидный Telegram `initData`:

```text
GET    /api/v1/admin/portfolio
POST   /api/v1/admin/portfolio
PATCH  /api/v1/admin/portfolio/{id}
DELETE /api/v1/admin/portfolio/{id}
POST   /api/v1/admin/portfolio/{id}/image
```

Изображения принимаются в JPEG, PNG или WebP размером до 8 МБ. В кабинете
мастера можно добавить работу, изменить название/место/теги/порядок, скрыть или
опубликовать её, загрузить новый файл и удалить запись. Скрытые работы не
попадают в публичный список и их бинарное изображение не отдаётся гостям.

Новая работа по умолчанию сохраняется скрытой. Публикация разрешена только
после указания `image_url` или загрузки изображения. Если мастер выбирает
публикацию вместе с новым файлом, Mini App сначала сохраняет скрытую запись,
загружает файл и только затем публикует её. При ошибке загрузки работа остаётся
скрытой, а форма сохраняется для повторной попытки. Миграция `009` также скрывает
ранее созданные опубликованные записи без источника изображения и добавляет
ограничение на уровне базы данных.

Категории портфолио («Графика», «Цвет», «Чёрное», «Ботаника») хранятся отдельно
от свободных тегов с описанием и настроением. Миграция `010` заполняет категории
старых работ по совпадающим техническим тегам; новые категории мастер выбирает
отдельно в форме. Миграция `011` отделяет папку портфолио от места на теле, не
меняя существующие места. Мастер может выбирать папку из существующих подсказок,
создавать новую вводом названия и переименовывать папку сразу у всех работ.

Перед публикацией и live-запуском отдельно проверьте:

1. Реальный Telegram webhook после заполнения `WEBHOOK_BASE_URL` и
   `WEBHOOK_SECRET`.
2. Подключение постоянной PostgreSQL. Если переходишь с SQLite, её данные
   автоматически не переносятся: сначала выгрузи и перенеси нужные данные
   либо явно реши, что старая база не нужна. `/api/v1/health` должен вернуть
   `database_backend: "postgresql"` и `data_persistent: true`.
3. Загрузку и публикацию одной тестовой работы через кабинет мастера, после
   чего проверить её в гостевом `/app/` и удалить тестовую запись.
